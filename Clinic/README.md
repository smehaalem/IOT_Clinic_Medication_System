# Patient Kiosk Module

This directory contains the patient-facing part of MedGate.

## Entry Point

```bash
cd Clinic
python3 kiosk_main.py
```

`kiosk_main.py` creates a stacked patient interface with the following screens:

1. Patient kiosk menu
2. Existing-patient check-in
3. New-patient registration
4. Existing-patient editing

The same router is embedded inside the complete application through `medication_sys/medicine_menu.py`.

## Files

### `kiosk_main.py`

Routes between the patient kiosk screens.

### `checkingui.py`

Handles returning-patient check-in.

- Accepts Personal ID or full name.
- Uses exact matching rather than partial-name matching.
- Displays the patient's stored profile after a successful search.
- Supports scanner input because the barcode scanner behaves like a keyboard.

### `add_patient_screen.py`

Creates a new patient record.

- Saves only fields that contain values.
- Automatically stores `ID Type` as `new`.
- Supports `Save`, `Save + Print`, and `Print Last`.
- Retrieves the generated Personal ID after creation.
- Produces a printable card containing the patient name, ID, and QR code.

### `edit_patient_screen.py`

Searches for and updates an existing patient.

- Searches by exact Personal ID or exact full name.
- Loads the selected Airtable record for editing.
- Supports saving, saving and printing, and deleting the patient.
- Personal ID and Manual ID are displayed as read-only identifiers.

### `printer_engine.py`

Generates and prints the patient identification label.

The printer-specific documentation file is intentionally left empty for project-specific completion:

```text
PRINT_ENGINE_README.md
```

### `config.py`

Loads Airtable credentials from environment variables or supported `.env` locations.

## Airtable Table

The patient screens use:

```text
Patients
```

Expected fields include:

```text
Name
Language
Gender
ID Type
Date of Birth
Phone
Emergy contact
City \ Unhoused
Referred by
Notes
Manual ID
Personal ID
```

`Personal ID` may be generated by Airtable. The code refreshes a newly created record before preparing the print data.

## Patient Card

The QR code contains only the raw patient ID. It does not contain the complete patient record.

The default print flow uses:

```text
CUPS queue: brotherql700
```

Generated image files are stored next to the patient code and should normally not be committed:

```text
last_patient_label.png
last_edited_patient_label.png
```

## Dependencies

```bash
python3 -m pip install PyQt5 pyairtable python-dotenv qrcode Pillow
```

The printer also requires CUPS and the `lp` command.

## Connectivity

The patient module communicates directly with Airtable. It does not currently use the medication subsystem's SQLite offline queue.
